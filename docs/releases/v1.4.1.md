# BondScore v1.4.1 — Multi-Platform Release + XChat DM Fix (X · Threads · Bluesky)

The biggest architectural update so far: BondScore is no longer X-only. The same
local-first relationship engine now runs on **X**, **Threads** and **Bluesky**,
with granular controls, platform-isolated records, a stricter privacy boundary,
and a refreshed iOS-glass interface.

## 🌐 What's New in v1.4.0

### 1. Multi-Platform Support
- **X stays on by default.** Threads and Bluesky are opt-in and start **off**.
- Every platform has a **master toggle** plus independent **Timeline** and **DMs**
  sub-toggles (`Settings → Platforms`).
- Disabled platforms/features observe nothing: no badge injection, no event
  writes, no DM metadata. Adapters fail closed.
- New passive adapters:
  - `content/platform-adapters.js` for Threads and Bluesky (identity, feed badges,
    profile signals, likes/reposts, DM metadata).
  - `content/xchat-adapter.js` for XChat: X moved DMs from `/messages` to
    `/i/chat`, rendered inside an **open shadow root**. The adapter observes that
    root so 1:1 and group DM scores work again; it reads only message ids,
    inbound/outbound alignment, public sender links and conversation titles.
  - Popup DM buttons use `https://x.com/messages/<a>-<b>` for 1:1 chats, because
    that legacy URL redirects into `/i/chat/<a>-<b>` **and** opens the thread,
    while loading `/i/chat/<id>` directly only mounts the shell. Group records
    point at the XChat inbox (`/i/chat`) since `/messages/g<id>` drops the id.
  - The X pipeline (`content.js`, `detector.js`) is preserved and now gated by the
    same switches.

### 2. Platform-Isolated Storage
- X keeps its legacy keys: `acc:<account>:user:<handle>`.
- Other networks use `acc:<account>:p:<platform>:…` for users, events and DMs.
- Caches are keyed `<platform>:<key>`, and every user/DM record carries a
  `platform` field.
- Leaderboard, DM dashboard, orbit, and exports can be filtered by platform with
  the new segmented capsule bar: **🌐 All · 𝕏 X · 🧵 Threads · 🦋 Bluesky**.
- Zero-migration upgrade: existing X data is untouched.

### 3. Strict Zero-Body DM Privacy
- **Message bodies are never read, parsed, hashed or stored** — not even a
  fingerprint derived from text.
- Removed the last DM `innerText` reads (inbox previews and conversation bodies);
  participant identity now comes from conversation ids, profile links and headers.
- DM fingerprints are metadata-only: `${direction}_${timestamp}_${index}`.
- Stored DM data is limited to handles, direction, timestamps, counts, reply
  latency, streaks and milestones.

### 4. Relationship & Group Taxonomy
- **Group energy:** ⚡ Energetic 80–100 · 🔥 Active 60–79 · ☕ Steady 40–59 ·
  🛋️ Chill 20–39 · 🪦 Dying < 20.
- **Relationship classes:** 🌟 Top Supporter · 🎯 Outbound Focus ·
  ⚖️ Balanced Mutual · ❄️ Dormant (14+ quiet days).
  These sit alongside the existing CRM statuses, so existing popup filters keep
  working.

### 5. iOS-Glass UI
- Apple-style glassmorphism: `blur(24px) saturate(190%)`, specular inset borders,
  and translucent cards.
- Apple Green `#34C759` capsule toggles with spring physics.
- Platform cards, capsule filters, and platform chips across CRM rows and DM
  cards. DM deep links now open the correct network.

### 6. Account Isolation Hardening
- Switching accounts now clears the DM cache as well as user/event caches.
- Non-X adapters detect the signed-in handle and switch the CRM account when it
  differs, preventing cross-account record bleed.

## 🧪 Tests
Run the Node suites directly:

```bash
node tests/dm-analytics.test.cjs
node tests/ui-regressions.test.cjs
node tests/platforms.test.cjs
node tests/xchat.test.cjs
```

`tests/platforms.test.cjs` covers defaults, master/sub-toggle gating, host
detection, platform key isolation, DM body privacy, energy thresholds and the
relationship classifier. `tests/xchat.test.cjs` covers XChat id canonicalisation,
group energy from metadata-only ingestion, and 1:1 DM scoring without ever
persisting message text.

## 🔄 Upgrade Notes
- No manual migration required.
- Threads/Bluesky remain off after upgrading; enable them in
  **Settings → Platforms**.
- Threads/Bluesky selectors are defensive and best-effort. If a network ships a
  major DOM redesign, the adapter stops rather than guessing; X is unaffected.
